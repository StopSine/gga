# Corrections to splat's function boundaries.
#
# splat locates function starts heuristically and sometimes splits one routine
# into several. N64Recomp reports this as:
#     Unhandled branch in <func> at <addr> to <target>
# because a branch target falls outside the function's declared range.
#
# Format: <function> <size>. Any function starting inside the widened range is
# absorbed automatically, so only the first function of a group needs an entry.
#
# Found by scanning the disassembly for branches that escape their enclosing
# function and unioning the affected functions: 11 escaping branches across
# 632 functions, forming the 3 groups below.

# Three-way split. Both later pieces branch back to .L80001190_1D90 and the
# routine's only `jr $ra` is at 0x8000128C, so it runs 0x80000F10..0x80001294.
func_80000F10_1B10 0x384

# Three-way split.
func_800013F0_1FF0 0x484

# Two-way split; the tail at func_80010294_10E94 branches back to 0x8001024C.
func_8000FD50_10950 0x62C

# Four-way split, and one the escaping-branch scan above cannot find: these
# pieces are straight-line code that falls through rather than branching, so no
# branch ever leaves the declared range. It was found instead by the symptom --
# the prologue `addiu $sp, $sp, -0x738` at 0x80001FA4 is emitted but the
# matching `addiu $sp, $sp, 0x738` at 0x80002054 is not, so the recompiled
# fragment returned 0x738 below the stack it was entered with and every later
# `lw` through $sp in the caller read the wrong frame.
#
# 0x20 + 0x14 + 0x10 + 0x88 = 0xCC, ending at the `jr $ra` at 0x80002058.
# Reached only once a formatted Controller Pak exists, which is why it stayed
# hidden until a real save was loaded.
func_80001F94_2B94 0xCC

# A switch, split into twelve pieces: the dispatcher plus one function per case,
# because each case is four instructions ending in `jr $ra`. Its jump table at
# 0x0800C58C therefore pointed entirely outside the function, N64Recomp could
# not determine the table's size, and it failed the whole function -- which is
# a hard error, so regeneration did not complete at all.
#
# This was previously worked around by patching N64Recomp to treat such a table
# as an indirect tail call. That was wrong: it is a real switch, and the table
# looked external only because the function was too small. Widening it to
# 0x08001794..0x08001884 fixes it with a stock recompiler.
func_08001794_660634 0xF0
